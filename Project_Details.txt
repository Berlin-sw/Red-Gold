NEW: HOW THE BACKEND & DATABASE WORKS (FOR YOUR PROFESSOR)
------------------------------------------------------------------

1. WHERE IS THE DATABASE?
The database is NOT stored on your computer. It is hosted on "MongoDB Atlas," which is a cloud database service (Database-as-a-Service). 
- Your connection string (MONGO_URL) in the .env file contains the secret credentials to talk to this cloud server.
- This allows your data to be accessible from anywhere and ensures it isn't lost if your computer shuts down.

2. HOW DOES THE DATABASE WORK?
- Type: It is a NoSQL (Non-Relational) database. Unlike Excel or SQL, it doesn't use rigid tables with rows and columns.
- Documents: Data is stored in "JSON-like" documents. Each user or blood record is a document.
- Collections: Related documents are grouped into "Collections" (like 'users' and 'inventories').
- Mongoose (The Bridge): We use a library called "Mongoose" to connect Node.js to MongoDB. It acts as an ODM (Object Data Modeling) tool, ensuring that every piece of data we save follows the rules (Schema) we defined in our models.

3. HOW DOES THE BACKEND WORK? (The Request Flow)
When a user clicks a button on the website (Frontend), here is what happens:
a) The Frontend sends a request (using Axios) to a specific URL (API Endpoint).
b) The Backend (Express server) receives the request in 'server.js'.
c) Middleware (authMiddleware) checks the "Security Badge" (JWT Token) to make sure the user is allowed to perform this action.
d) The Router directs the request to the correct 'Controller'.
e) The Controller performs the logic (e.g., calculating available blood or checking a password).
f) The Controller talks to the Database via Mongoose to fetch or save data.
g) The Database sends the result back to the Controller.
h) The Controller sends a JSON Response back to the Frontend (Success/Failure).
i) The Frontend updates the screen so the user sees the result.

1. PROJECT OVERVIEW
-------------------
This is a Full-Stack Web Application built using the MERN (MongoDB, Express.js, React.js, Node.js) stack. The system manages blood donations, inventory, and requests between Donors, Hospitals, and Organizations. It features a role-based access system for Admins, Organizations, Donors, and Hospitals.

2. BACKEND ARCHITECTURE (Node.js & Express)
-------------------------------------------

A. Entry Point: server.js
- Configures the Express server.
- Connects to MongoDB via config/db.js.
- Loads environment variables (PORT, MONGO_URL, JWT_SECRET).
- Defines API routes for authentication, inventory, analytics, and admin tasks.

B. Database Configuration: config/db.js
- Function: connectDB()
- Connects the application to MongoDB Atlas using Mongoose. Logs connection success or failure.

C. Models (Database Schemas):
1. userModel.js:
   - Stores user details (name, email, password, role, address, phone).
   - Roles include: 'admin', 'organisation', 'donar', 'hospital'.
2. inventoryModel.js:
   - Tracks blood records.
   - Fields: inventoryType (IN/OUT), bloodGroup (A+, O-, etc.), quantity, email, and references to the donor, hospital, and organisation.

D. Controllers (Business Logic):
1. authController.js:
   - registerController: Validates if a user exists, hashes passwords using bcrypt, and saves the new user.
   - loginController: Verifies email/password and returns a JWT (JSON Web Token) for authentication.
   - currentUserController: Fetches details of the currently logged-in user using their ID from the token.

2. inventoryController.js:
   - createInventoryController: Adds new blood records. If the type is 'OUT', it performs a complex aggregation check to ensure sufficient blood quantity is available before allowing the transaction.
   - getInventoryController: Fetches all blood records related to a specific organization.
   - getDonarsController: Uses Mongoose .distinct() to find all unique donors who have donated to an organization.
   - getHospitalController: Finds unique hospitals that have received blood from an organization.

3. analyticsController.js:
   - bloodGroupDetailsContoller: A powerful function that uses MongoDB Aggregation ($match, $group, $sum) to calculate Total In, Total Out, and Available Blood for every blood group (A+, B+, O+, etc.).

4. adminController.js:
   - Contains administrative functions to fetch lists of all Donors, Hospitals, and Organizations and delete records if necessary.

E. Middleware:
- authMiddleware.js: Intercepts incoming requests, extracts the JWT from the header, verifies it, and attaches the user ID to the request object.
- adminMiddleware.js: Ensures that only users with the 'admin' role can access specific administrative routes.

3. FRONTEND ARCHITECTURE (React.js)
-----------------------------------

A. Main App: App.js
- Defines the routing structure using React Router.
- Uses ProtectedRoute (requires login) and PublicRoute (redirects logged-in users away from Login/Register).

B. State Management: Redux (redux/store.js)
- Manages the global authentication state (user data, login status, loading states).
- redux/features/auth/authSlice.js: Defines the initial state and reducers to handle success/failure of authentication.
- redux/features/auth/authActions.js: Contains "Thunks" (async actions) for user login, registration, and fetching the current user profile. It handles the API communication and dispatches results to the slice.

C. Pages:
- HomePage.js: The main dashboard showing summary statistics (Total In, Total Out, Net Available) and a searchable table of recent records.
- Analytics.js: Visualizes blood availability using color-coded cards for each blood group.
- Login/Register: Handles user authentication using the authService.

D. Services: services/API.js
- Creates a centralized Axios instance with a base URL and automatically attaches the JWT token to every request's header.

4. KEY TECHNICAL FEATURES
-------------------------
- Security: Passwords are encrypted using bcryptjs.
- Authentication: Secure stateless authentication using JSON Web Tokens (JWT).
- Data Integrity: Aggregation pipelines ensure hospitals cannot request more blood than what is available in the inventory.
- UI/UX: Modern Glassmorphic design with responsive tables and interactive modals.
- Real-time Feedback: Integrated toast notifications for success and error messages.
